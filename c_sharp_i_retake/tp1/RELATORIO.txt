Exercício 2 — Portabilidade

O compilador C# transforma o código-fonte em IL (Intermediate Language),
uma representação intermediária armazenada em um assembly, junto a metadados.
Essa IL não é o código de máquina específico de Windows ou Linux.
Em cada sistema, uma implementação compatível do runtime .NET carrega o assembly.
O CLR gerencia a execução e usa o compilador JIT para traduzir os métodos em IL
para código de máquina adequado à arquitetura durante a execução.
A CPU executa esse código nativo produzido pelo JIT, não a IL diretamente.
Assim, o mesmo assembly pode funcionar nos dois sistemas quando o runtime e
as dependências são compatíveis e o programa evita recursos específicos do SO.

Exercício 3 — Compilação e execução

Após DOTNET_CLI_HOME=/tmp/infnet-dotnet dotnet build, bin/Debug/net10.0 contém:
- AmbienteEstacionamento.dll: assembly com IL e metadados do programa.
- AmbienteEstacionamento.pdb: símbolos usados para depuração.
- AmbienteEstacionamento.deps.json: informações das dependências da aplicação.
- AmbienteEstacionamento.runtimeconfig.json: framework e configurações do runtime.
- AmbienteEstacionamento: executável nativo de inicialização gerado nesta máquina.

O SDK reúne as ferramentas necessárias para criar, compilar e executar projetos,
incluindo o CLI e o compilador C# Roslyn. O Roslyn analisa o código-fonte
e produz um assembly com IL e metadados. O CLR carrega esse assembly e gerencia
a execução, incluindo a tradução JIT dos métodos e a coleta de memória.
A Base Class Library (BCL) fornece tipos e funcionalidades reutilizáveis,
como Console e Environment, usados pelo programa para saída e informações
do ambiente. A implementação da biblioteca e do runtime para cada plataforma
permite que essas APIs sejam usadas em sistemas operacionais diferentes.

Ciclo de vida:
1. Escrever ou editar o código-fonte em Program.cs.
2. Executar dotnet build: o SDK usa o Roslyn para compilar C# em IL no assembly.
3. Iniciar o programa: o runtime é escolhido e o CLR carrega o assembly.
4. O JIT compila os métodos necessários de IL para código de máquina nativo.
5. A CPU executa o código nativo, sob gerenciamento do runtime.
